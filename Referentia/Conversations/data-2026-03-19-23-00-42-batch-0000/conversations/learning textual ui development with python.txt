---

**What is Textual?**

Textual is a Python framework (built on top of `rich`) that lets you create 
full-featured terminal applications with widgets, layouts, and interactivity 
— kind of like web development but for the terminal.

---

**Step 1: Install Textual**

```bash
pip install textual
```

To also get the developer tools (highly recommended):

```bash
pip install textual-dev
```

---

**Step 2: Your First App**

Here's the absolute simplest Textual app:

```python
from textual.app import App, ComposeResult
from textual.widgets import Static

class MyApp(App):
    def compose(self) -> ComposeResult:
        yield Static("Hello, World!")

if __name__ == "__main__":
    MyApp().run()
```

Save it as `hello.py` and run it with `python hello.py`. Press `Ctrl+C` to quit.

**What's happening here?**

- `App` is the base class for every Textual application.
- `compose()` is where you define what widgets appear on screen — you `yield` 
them like a generator.
- `Static` is the simplest widget: it just displays text.

---

**Step 3: Adding a quit keybinding**

```python
from textual.app import App, ComposeResult
from textual.widgets import Static

class MyApp(App):
    BINDINGS = [("q", "quit", "Quit")]

    def compose(self) -> ComposeResult:
        yield Static("Hello, World!\n\nPress Q to quit.")

if __name__ == "__main__":
    MyApp().run()
```

`BINDINGS` is a class-level list where you map keys → actions → 
descriptions. `"quit"` is a built-in action provided by `App`.

---

**Step 4: The Textual dev console**

While your app is running, open a second terminal and run:

```bash
textual console
```

Then run your app with:

```bash
textual run --dev hello.py
```

This gives you a live log of events, which is incredibly helpful for learning 
and debugging.

---

**The Learning Path I'd Suggest**

Going from where you are, a good progression looks like this:

1. `Static` widget → display text
2. `Button` widget → handle clicks
3. `Label` + `Input` → capture user input
4. Layouts (`Horizontal`, `Vertical`, `Grid`) → arrange widgets
5. CSS styling → Textual has its own `.tcss` stylesheet system
6. Reactive attributes → auto-update the UI when data changes
7. Custom widgets → build your own reusable components
8. Workers & async → run background tasks without freezing the UI

Claude:  Sure!

```python
from textual.app import App, ComposeResult
```

`textual.app` is the core module of the Textual framework. From it you're 
importing two things:

- **`App`** — the base class for your application. Every Textual app starts 
by creating a class that inherits from this. It handles the event loop, 
rendering, keyboard input, and everything else behind the scenes.
- **`ComposeResult`** — this is just a type hint. It tells Python (and your 
editor) what `compose()` is expected to return. It doesn't change how the code 
runs, but it's good practice.

```python
from textual.widgets import Static
```

`textual.widgets` is where all the built-in UI components live. **`Static`** is 
the simplest one — it just displays text on screen and doesn't do anything 
interactive.

As we progress you'll be importing more widgets from this same module, things 
like `Button`, `Input`, `Label`, and so on.
