Claude:  Good. On composition — here's the distinction plainly:

**Hardcoded layout** means the Python file itself defines what goes where. You 
change the layout by editing the code. Fast, no infrastructure, but to try a 
new arrangement you open the file and move things around.

**Config-driven** means a YAML or JSON file says something like:
```yaml
grid:
  rows: 3
  cols: 2
  cells:
    - [0,0]: rune_field
    - [0,1]: text_display
    - [1,0]: border_frame
```
...and the app reads that file and builds the layout dynamically. Slower to set 
up initially, but once it's working you can audition entirely new arrangements 
by editing the YAML — no code changes.

**Eventually both** means: build hardcoded first so you can move fast and see 
results immediately, then once you know what the pane vocabulary *is*, 
formalize a schema so you can compose layouts without touching Python.
