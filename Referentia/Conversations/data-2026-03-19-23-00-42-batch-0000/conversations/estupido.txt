### Step 1 — Write `db.py`

```bash
cat > ~/estupido/db.py << 'EOF'
import sqlite3
import os

DB_PATH = os.path.join(os.path.dirname(__file__), "estupido.db")

class EstupidoDB:
    def __init__(self):
        self.conn = sqlite3.connect(DB_PATH)
        self.create_tables()

    def create_tables(self):
        with self.conn:
            self.conn.executescript("""
                CREATE TABLE IF NOT EXISTS phrases (
                    id          INTEGER PRIMARY KEY AUTOINCREMENT,
                    english     TEXT NOT NULL,
                    spanish     TEXT NOT NULL,
                    tag         TEXT DEFAULT 'General'
                );

                CREATE TABLE IF NOT EXISTS global_vocab (
                    id          INTEGER PRIMARY KEY AUTOINCREMENT,
                    word        TEXT NOT NULL,
                    definition  TEXT NOT NULL
                );

                CREATE TABLE IF NOT EXISTS slang (
                    id              INTEGER PRIMARY KEY AUTOINCREMENT,
                    english         TEXT NOT NULL UNIQUE,
                    mexican_spanish TEXT NOT NULL
                );
            """)

    # --- PHRASES ---
    def save_phrase(self, english, spanish, tag="General"):
        with self.conn:
            self.conn.execute(
                "INSERT INTO phrases (english, spanish, tag) VALUES (?, ?, ?)",
                (english, spanish, tag)
            )

    def get_phrases(self, limit=15, tag=None):
        if tag:
            return self.conn.execute(
                "SELECT id, english, spanish, tag FROM phrases WHERE tag=? 
ORDER BY id DESC LIMIT ?",
                (tag, limit)
            ).fetchall()
        return self.conn.execute(
            "SELECT id, english, spanish, tag FROM phrases ORDER BY id DESC 
LIMIT ?",
            (limit,)
        ).fetchall()

    # --- WORD OF THE DAY ---
    def get_wod(self):
        res = self.conn.execute(
            "SELECT word, definition FROM global_vocab ORDER BY RANDOM() LIMIT 
1"
        ).fetchone()
        return res if res else ("¡ESTUPIDO!", "No words yet. Add vocab to see 
WOD.")

    def seed_vocab(self):
        """Seed a starter set of vocab if table is empty."""
        count = self.conn.execute("SELECT COUNT(*) FROM 
global_vocab").fetchone()[0]
        if count == 0:
            starter = [
                ("trabajo", "work / job"),
                ("ayuda", "help"),
                ("descanso", "break / rest"),
                ("herramienta", "tool"),
                ("cuidado", "careful / watch out"),
                ("despacio", "slowly"),
                ("terminar", "to finish"),
                ("mañana", "tomorrow / morning"),
                ("almuerzo", "lunch"),
                ("jefe", "boss"),
            ]
            with self.conn:
                self.conn.executemany(
                    "INSERT INTO global_vocab (word, definition) VALUES (?, ?)",
                    starter
                )

    # --- SLANG ---
    def save_slang(self, english, mexican_spanish):
        with self.conn:
            self.conn.execute(
                "INSERT OR REPLACE INTO slang (english, mexican_spanish) VALUES 
(?, ?)",
                (english, mexican_spanish)
            )

    def get_slang(self, english):
        res = self.conn.execute(
            "SELECT mexican_spanish FROM slang WHERE english=?",
            (english.lower(),)
        ).fetchone()
        return res[0] if res else None

    def get_all_slang(self):
        return self.conn.execute(
            "SELECT english, mexican_spanish FROM slang"
        ).fetchall()

    def close(self):
        self.conn.close()
EOF
```

## Redesign Plan

### What's changing

**Database** — `db.py` needs a full overhaul. The current single `phrases` 
table gets replaced with:

- `vocabulary` — single words, with english, spanish, phonetic, 
part\_of\_speech, topic\_tags, custom\_tags, date\_saved
- `phrases` — multi-word, with english, spanish, topic\_tags, custom\_tags, 
date\_saved
- `slang_results` — saved slangified versions, with original\_en, 
original\_es, slang\_es, date\_saved
- `slang` table stays as-is (the override dictionary)

**New file: `enrichment.py`** — Merriam-Webster API wrapper. Takes a word, 
returns phonetic pronunciation, part of speech, short definition, and synonyms. 
Sits completely separate from `api.py`.

**New file: `dialogs.py`** — The save/tag dialog as a Textual `ModalScreen`. 
Shows auto-suggested tags, lets user accept/decline each, add custom tags, 
choose vocab vs phrase override, then Save or Cancel.

**Updated `api.py`** — Add a `slangify()` function that sends the Spanish 
result back to DeepL with a prompt to return a casual Mexican slang equivalent.

**Updated `app.py`** — The big changes:
- Each translation result renders as a widget with Save and Discard buttons
- Selecting Save opens the tag dialog
- Selecting Discard removes that result from the view
- Menu gets `VOCABULARY` and `PHRASES` as separate items replacing `LIBRARY`
- Vocabulary and Phrases views show category submenus in the left pane
- Selecting an item opens a detail view in center pane
- Right pane vocab list is browseable while composing in translate view
- Slangify button appears on saved results, `/slangify` command works on last 
result
- Slangify shows side-by-side diff view with highlights

**Stack options**

**Voice in / Voice out**

For voice input, Expo has `expo-speech-recognition` which taps the phone's 
native speech-to-text — so on Android it uses Google's engine, on iOS it uses 
Siri's. No extra API key needed, works offline for common words. You speak 
English, it transcribes, sends to DeepL, gets Spanish back.

For voice output, `expo-speech` reads the Spanish translation aloud using the 
device's TTS engine. You'd want to set the language to `es-MX` for Mexican 
Spanish accent.

The flow would be: **hold button → speak English → release → DeepL 
translates → phone speaks Spanish aloud**. Like a walkie-talkie. That's the 
killer feature for on-site use with your colleagues — no typing, no screen, 
just talk.

```
                  MW API
```

The desktop app would switch from importing `db.py` directly to calling the API 
instead. Or you keep the direct DB connection for when you're at your desk and

**What the API needs to expose**

Minimal endpoints to support the phone:

- `POST /translate` — text in, Spanish out (DeepL call server-side)
- `POST /vocab` — save a word with tags
- `POST /phrases` — save a phrase with tags  
- `GET /vocab` — fetch list (for review on desktop)
- `GET /phrases` — fetch list
- `GET /quick-phrases` — static list by category
- `POST /slangify` — slangify a result
- `GET /wod` — word of the day

The phone never talks to DeepL or MW directly — the server handles all API 
calls. Your keys stay on the server, never in the phone app.

**Phone app feature set** — deliberately minimal:

- Hold-to-talk → transcribe → translate → speak result aloud
- One-tap save (no tagging on the phone — just capture, tag later on desktop)
- Quick phrases by category, tap to hear spoken aloud
- Recent translations list
- Word of the day

**Sync**

If the server is running on your home network, the phone connects over WiFi. 
When you're on site without WiFi, the phone queues unsaved items locally and 
syncs when you reconnect. That's the offline-first pattern.
