---

**The Key Technical Wrinkle: Async vs Sync**

Most of these are **async** — you POST a job, get back a task ID, then poll 
`GET` to check status until the image is ready. A few (like Flux Reimagine 
beta) appear to be synchronous. Your UI needs to handle this gracefully — a 
"generating..." state with polling, not just fire-and-forget.

Mystic specifically requires a **webhook** to retrieve results, which adds a 
layer of complexity. You'd either need a lightweight local HTTP server to 
receive the webhook, or you could poll for it differently.

---

**TUI vs Qt — my honest take**

Given that you're receiving and displaying actual images, I'd lean toward **Qt 
(PyQt6 or PySide6)** rather than a TUI. Here's why:

- Image rendering in a TUI is possible (kitty/sixel protocol) but finicky and 
not universally supported
- Qt gives you a real image viewer, zoom, save dialog — all native
- Parameter forms (sliders, dropdowns, number spinners) feel much more natural 
in Qt
- You already have PySide/PyQt experience territory from your Python work

A TUI with Textual *could* work if you're dead set on terminal — you'd 
display image previews as sixel or just show a thumbnail path and open in the 
system viewer. But for an image-centric app, Qt is the right call.

**The Key Design Decisions**

**Model definitions as data, not code.** Instead of writing a separate class 
per model, define all 14-15 models in a single `models.py` as Python 
dataclasses or dicts — each entry describes its endpoint, its parameters 
(name, type, range/options, default). The `param_panel` reads this and builds 
the form dynamically. Adding a new model later is just adding a new entry to 
the list.

**One worker pattern for all async models.** Every model follows the same flow: 
POST → get task_id → poll GET until status is `done` → fetch image URL. 
Write that loop once in `worker.py`, parameterize it with the endpoint. 
Mystic's webhook requirement is the one exception — handle it by falling back 
to polling the task status endpoint anyway (Freepik supports both).

**Image viewer is just a QLabel with a pixmap.** Keep it simple. Scale to fit 
the panel, right-click or button to save. No need for a full QGraphicsView with 
zoom unless you want to add it later as a stretch goal.

**Prompt improver as an optional button.** The improve-prompt endpoint is 
genuinely useful — a single "✨ Enhance" button next to the prompt field 
adds real value with almost zero extra code.
