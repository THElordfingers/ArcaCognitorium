Konsole doesn't actually use JSON for its layout files — it uses `.konsole` 
profile files (INI format) and session/layout files in a different format. Let 
me clarify what's available:

**What Konsole actually uses:**

- **Profiles** — `.profile` files stored in `~/.local/share/konsole/`, INI 
format
- **Session layouts** — `.konsole` files, also INI format  
- **Split view layouts** — saved as part of the session state, not standalone 
JSON

Here are examples of the actual formats:

**A profile file** (`~/.local/share/konsole/MyProfile.profile`):
```ini
[Appearance]
ColorScheme=Catppuccin-Mocha
Font=JetBrains Mono,11,-1,5,50,0,0,0,0,0

[General]
Name=MyProfile
Parent=FALLBACK/
Command=/bin/bash
TerminalColumns=120
TerminalRows=30

[Scrolling]
ScrollBarPosition=2
ScrollbackLines=5000

[Terminal Features]
BlinkingCursorEnabled=true
```

**A saved session file** (`~/.local/share/konsole/mysession.konsole`):
```ini
[Desktop Entry]
Icon=utilities-terminal
Type=Application

[Terminal0]
Profile=MyProfile
Title=Main

[Terminal1]
Profile=MyProfile
Title=Monitor

[ViewSplitter0]
Orientation=Horizontal

[ViewSplitter0.View0]
Type=Terminal
TerminalIndex=0

[ViewSplitter0.View1]
Type=Terminal
TerminalIndex=1
```

Claude:  Good task for a bash script. The key pieces you need to capture per terminal

- Working directory
- Whether it's running an editor (`nvim`, `nano`, etc.) with a specific file
- Which Konsole profile to use
- Window geometry / which monitor

**The approach:** snapshot your current terminals, generate a reopen script.

The tricky part is that Konsole exposes session info via D-Bus. Here's how to 
pull it:

```bash
# List all Konsole instances and their sessions
qdbus | grep konsole
```

```bash
# For a specific Konsole instance, list sessions
qdbus org.kde.konsole-<PID> /Windows/1 org.kde.konsole.Window.sessionList
```

```bash
# Get the current directory of a session
qdbus org.kde.konsole-<PID> /Sessions/<N> 
org.kde.konsole.Session.currentWorkingDirectory
```

```bash
# Get the current running command/title
qdbus org.kde.konsole-<PID> /Sessions/<N> org.kde.konsole.Session.title 0
```

Here's a template built around your use case:

```bash
#!/usr/bin/env bash
# 
──────────────────────────�
�──────────────────────────�
��───────
#  workspace.sh — restore Konsole workspace
# 
──────────────────────────�
�──────────────────────────�
��───────

# Helper: open a Konsole window at a directory, optionally opening a file
open_term() {
    local dir="$1"
    local file="$2"   # optional

    if [[ -n "$file" ]]; then
        konsole --workdir "$dir" -e nvim "$file" &
    else
        konsole --workdir "$dir" &
    fi

    sleep 0.3   # brief pause so windows don't stack on top of each other
}

# ── Your windows 
──────────────────────────�
�───────────────────

open_term ~/projects/LuxArcana
open_term ~/projects/LuxArcana "src/main.py"
open_term ~/projects/ESTUPIDO "estupido/app.py"
open_term ~/notes "todo.md"
open_term ~
```

**A few things to tune:**

- Replace `nvim` with whatever editor you use (`nano`, `hx`, etc.)
- The `sleep 0.3` just staggers launches slightly — increase it if windows 
are opening chaotically
- `--workdir` sets the starting directory even when launching an editor

**To install it:**
```bash
chmod +x ~/workspace.sh
```

Then just run `~/workspace.sh` or bind it to a key in KDE's shortcuts.

---

**One thing worth knowing:** `konsole -e nvim file` opens the editor but when 
you quit the editor, that terminal closes too (since the editor was the 
launched process). If you want the terminal to stay open after quitting the 
editor, swap to:

```bash
konsole --workdir "$dir" -e bash -c "nvim '$file'; exec bash" &
```

That drops you back to a shell after exiting the editor instead of closing the 
window. Want me to bake that into the script by default?

LordFingers: using konsole --geometry nxn+n+n, the windows open the right size but it 
ignores the placement

Claude:  Known Konsole quirk — KDE's window manager (KWin) overrides placement and 
ignores the geometry hint for position. The size part of `--geometry` gets 
respected but the `+x+y` offset gets thrown away.

The fix is to use `wmctrl` or `xdotool` to move the window after it opens, 
since those talk directly to KWin:

```bash
open_term() {
    local dir="$1"
    local file="$2"
    local geometry="$3"   # e.g. "1200x800"
    local x="$4"
    local y="$5"

    if [[ -n "$file" ]]; then
        konsole --workdir "$dir" --geometry "$geometry" -e bash -c "nvim 
'$file'; exec bash" &
    else
        konsole --workdir "$dir" --geometry "$geometry" &
    fi

    local pid=$!

    # Wait for the window to appear, then move it
    sleep 0.6
    wmctrl -r :ACTIVE: -e 0,"$x","$y",-1,-1
}

# ── Your windows 
──────────────────────────�
�───────────────────

open_term ~/projects/LuxArcana "" "1200x800" 0 0
open_term ~/projects/LuxArcana "src/main.py" "1200x800" 1220 0
open_term ~/notes "todo.md" "800x600" 0 820
```

The `-e 0,x,y,-1,-1` means: move to x,y, leave width/height alone (`-1` = don't 
change).

**Check if wmctrl is installed:**
```bash
which wmctrl || sudo apt install wmctrl
```

---

**The catch** with `:ACTIVE:` is that if focus shifts between the `&` launch 
and the `wmctrl` call, it'll move the wrong window. A more reliable approach 
targets by PID if you need precision:

```bash
# Wait for the window to register, get its ID by PID
sleep 0.6
WID=$(wmctrl -lp | awk -v pid="$pid" '$3 == pid {print $1; exit}')
if [[ -n "$WID" ]]; then
    wmctrl -ir "$WID" -e 0,"$x","$y",-1,-1
fi
```

That matches the exact window spawned rather than whatever happens to be 
focused. Want me to write the full script with that baked in?
