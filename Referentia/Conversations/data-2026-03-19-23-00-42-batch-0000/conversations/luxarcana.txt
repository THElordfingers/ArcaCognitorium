Here's the full reverse-engineering write-up. Here's a summary of what was 
decoded:

**Protocol basics:** All commands are 9-byte BLE GATT Write Commands 
(no-response) to handle `0x0009`, framed `7e...ef`.

**Command families identified by byte 2:**
- `04` — Power ON/OFF (`ff` = on, `00` = off)
- `05 03` — Static RGB color (bytes 4–6 = R, G, B; byte 7 = `10`)
- `01` — Brightness (byte 3 = 0x00–0x64 = 0–100%)
- `03` — Built-in animation modes (byte 3 = mode ID, byte 4 = speed)
- `02` — Animation speed (byte 3 = 0x00–0x64)
- `fd` — Music mode select (modes 01–06 = 
generic/soft/dynamic/disco/classic/+1)
- `06` — Music sensitivity (byte 3 = 0x00–0x64)
- `82` — Schedule (on/off toggle + time setting)

**Key patterns:** Commands are always sent in duplicate pairs (~14ms apart) for 
reliability. Unused bytes are padded with `0xff`. Sliders stream packets 
continuously — you can just send one packet with the target value from Python.

The document includes ready-to-use Python helper functions and a `bleak` 
connection example for your PC script. The schedule encoding is partially 
inferred — a few more targeted captures would nail those bytes down 
completely.

Claude:  That's a really good idea. Instead of collapsing everything to one average 
colour, you'd:

1. Sample the screen
2. Cluster the pixels into N dominant colours (like a palette extraction)
3. Cycle through them with smooth transitions — not a hard flicker, but a 
drift that follows the weight of each colour (dominant colours get more dwell 
time)

So if your screen is mostly dark blue with some orange highlights and white UI 
chrome — you'd ignore the chrome, spend most time on the blue, occasionally 
drift into the orange. It actually *feels* like the screen.

The interesting design questions:

**How many colours?** 3–5 is probably the sweet spot. 2 feels mechanical, 6+ 
and the transitions happen too fast to read.

**How do you cluster?** K-means on the pixel data is the classic approach but 
it's slow. A faster approximation is to quantize to a coarse colour cube and 
take the top N buckets by pixel count. Good enough and runs in milliseconds.

**What do you ignore?** Near-black (luma < 15%), near-white (luma > 85%), and 
highly desaturated greys — those are UI chrome, not content. Throw them out 
before clustering. What's left is the actual palette of whatever you're 
watching or working on.

**How do you transition?** Don't flicker — lerp smoothly between the current 
colour and the next target over maybe 0.5–2 seconds depending on how 
different they are. Bigger colour distance = slower transition so it doesn't 
feel jarring.

**Dwell time** proportional to pixel count — if orange is 60% of the screen 
and blue is 40%, orange gets 60% of the time.

Here's exactly what the new `ScreenEngine` does:

**Palette extraction (thread-side, every 0.5s):**
Grabs a 12×12 sample grid from the screen — 144 pixels, fast enough to run 
constantly. Computes luma and saturation for each, then throws away anything 
near-black (luma < 25), near-white (luma > 230), or desaturated (sat < 0.12) 
— that's all the UI chrome, window borders, taskbar. What's left gets 
quantised into an 8×8×8 colour cube and the top N buckets by pixel count 
become the palette, each carrying a weight proportional to how many pixels it 
represents.

**Animation (async-side, continuous):**
Picks the next target colour with weighted random selection — so if your 
screen is 60% deep blue and 20% orange and 20% red, it'll spend most of its 
time near blue, occasionally wandering into orange or red. Then either:

- **Smooth lerp** (80% of the time by default): glides to the target over 
0.4–2.5 seconds with a smoothstep ease, then dwells there for 0.3–3 seconds 
— all random, all different lengths so it never feels mechanical
- **Flicker** (20% by default): snaps to a random palette colour for 1–4 very 
brief frames (30–100ms each), optional dark dip between frames to make it 
feel electric, then resumes

**Two live sliders:**
- **PAL** — palette size 2–6. Fewer colours = more focused, stays near the 
dominant mood. More = wider wandering, more variety
- **FLK** — flicker probability 0–40%. Zero makes it purely organic and 
smooth. High makes it restless and alive

Claude:  **Project structure**

Single file is genuinely fine for this project. The codebase is maybe 
1500–2000 lines max, you run it with `python3 lux_arcana.py`, git diff is 
readable, and there's no import complexity. The only real argument for a

---

**TUI framework**

*Textual* — what we've been using. Genuinely powerful, great widget system, 
handles layout well. The problem we kept hitting is that its CSS layout engine 
has quirks that are hard to debug without a browser devtools equivalent. When 
something doesn't appear, you're guessing. It's also somewhat heavy — startup 
is sluggish.

*blessed* — thin wrapper around curses. You draw everything yourself: "print 
this string at column X, row Y, in this colour." Zero magic, zero layout 
engine, zero mystery. The downside is you're responsible for every pixel. For 
something like a colour wheel and sliders that's maybe 200 lines of drawing 
code — totally manageable, and you'll never wonder why your tabs are 
invisible.

*urwid* — middle ground. Has a widget system and layout engine like Textual 
but older, more battle-tested, lighter. Honestly less pleasant to work with 
than either extreme.

*raw curses* — same as blessed but more painful. Blessed is just curses with 
a nicer API. No reason to go lower.

My honest take: **blessed**. For LuxArcana specifically — a fixed layout with 
a colour picker, some buttons, a log panel — you don't need a framework's 
layout engine. You know exactly what the screen looks like. Drawing it directly 
means it always looks exactly right, runs instantly, and there's nothing 
between you and the output. The "complexity" is just learning to think in x/y 
coordinates instead of CSS, which takes about an hour.

"""
audio.py — system audio reactive effect

Captures system audio via parec (PulseAudio/PipeWire record tool)
piped directly into Python. No sounddevice required.

Two colour modes:
  "amplitude"  — hue fixed to base_rgb; brightness pulses with volume
  "spectrum"   — low frequencies → red/warm, highs → blue/cool

Parameters:
  mode          "amplitude" | "spectrum"  (default "amplitude")
  sensitivity   1–100  (default 70)
  base_rgb      (r, g, b)
  smoothing     0–100  (default 40)
  rgb_fn        callable(r,g,b) -> bytes
"""

import asyncio
import colorsys
import logging
import subprocess
import numpy as np
from typing import Callable, Optional, Tuple

from .effects import Effect, register

log = logging.getLogger(__name__)

CHUNK            = 1024
SAMPLERATE       = 44100
CHANNELS         = 2
BYTES_PER_SAMPLE = 2   # s16le


def _find_monitor_source() -> Optional[str]:
    """Return the name of the RUNNING monitor source via pactl."""
    try:
        out = subprocess.check_output(
            ["pactl", "list", "sources", "short"],
            text=True, timeout=3)
        for line in out.splitlines():
            if "monitor" in line and "RUNNING" in line:
                return line.split()[1]
        for line in out.splitlines():
            if "monitor" in line:
                return line.split()[1]
    except Exception as e:
        log.debug("pactl failed: %s", e)
    return None


@register("audio")
class AudioEffect(Effect):

    NAME = "audio"

    def __init__(self, send_fn: Callable,
                 mode: str = "amplitude",
                 sensitivity: int = 70,
                 base_rgb: Tuple[int, int, int] = (255, 160, 60),
                 smoothing: int = 40,
                 device: Optional[int] = None,
                 rgb_fn: Optional[Callable] = None):
        super().__init__(send_fn)
        self.mode        = mode if mode in ("amplitude", "spectrum") else 
"amplitude"
        self.sensitivity = max(1, min(100, sensitivity))
        self.base_rgb    = base_rgb
        self.smoothing   = max(0, min(100, smoothing))
        self._rgb_fn     = rgb_fn or (lambda r, g, b: bytes([
            0x7e, 0x07, 0x05, 0x03,
            r & 0xff, g & 0xff, b & 0xff,
            0x10, 0xef]))

    async def _run(self) -> None:
        source = _find_monitor_source()
        if not source:
            log.error("audio: no monitor source found — is audio playing?")
            return

        log.info("audio: recording from %s", source)

        frame_bytes = CHUNK * CHANNELS * BYTES_PER_SAMPLE

        cmd = [
            "parec",
            "--device", source,
            "--format=s16le",
            f"--rate={SAMPLERATE}",
            f"--channels={CHANNELS}",
            "--latency-msec=50",
        ]

        proc = await asyncio.create_subprocess_exec(
            *cmd,
            stdout=asyncio.subprocess.PIPE,
            stderr=asyncio.subprocess.DEVNULL,
        )

        log.info("audio effect started  mode=%s  sensitivity=%d",
                 self.mode, self.sensitivity)

        smooth_alpha = self.smoothing / 100.0
        cur_r, cur_g, cur_b = self.base_rgb
        sens = self.sensitivity / 100.0

        try:
            while self.running:
                raw     = await proc.stdout.readexactly(frame_bytes)
                samples = np.frombuffer(raw, dtype=np.int16).astype(np.float32) 
/ 32768.0
                rms     = float(np.sqrt(np.mean(samples ** 2)))
                amp     = min(1.0, rms * sens * 80.0)

                if self.mode == "amplitude":
                    h, s, v = colorsys.rgb_to_hsv(
                        self.base_rgb[0] / 255,
                        self.base_rgb[1] / 255,
                        self.base_rgb[2] / 255,
                    )
                    nr, ng, nb = colorsys.hsv_to_rgb(h, s, amp)
                    tr, tg, tb = int(nr*255), int(ng*255), int(nb*255)

                else:  # spectrum
                    mono  = samples[::2] + samples[1::2]
                    fft   = np.abs(np.fft.rfft(mono))
                    n     = len(fft)
                    low   = float(np.mean(fft[:n // 4]))
                    high  = float(np.mean(fft[n // 4:]))
                    total = low + high + 1e-9
                    hue   = 0.6 * (high / total)
                    nr, ng, nb = colorsys.hsv_to_rgb(hue, 0.9, amp)
                    tr, tg, tb = int(nr*255), int(ng*255), int(nb*255)

                a     = smooth_alpha
                cur_r = int(cur_r * a + tr * (1 - a))
                cur_g = int(cur_g * a + tg * (1 - a))
                cur_b = int(cur_b * a + tb * (1 - a))

                pkt = self._rgb_fn(cur_r, cur_g, cur_b)
                await self._send(pkt)

        except asyncio.IncompleteReadError:
            log.warning("audio: parec stream ended")
        except asyncio.CancelledError:
            raise
        except Exception as e:
            log.error("audio effect error: %s", e)
        finally:
            try:
                proc.terminate()
                await proc.wait()
            except Exception:
                pass
            log.info("audio effect stopped")


def list_input_devices() -> list:
    try:
        out = subprocess.check_output(
            ["pactl", "list", "sources", "short"], text=True, timeout=3)
        result = []
        for line in out.splitlines():
            parts = line.split()
            if len(parts) >= 2:
                result.append({
                    "index":   parts[0],
                    "name":    parts[1],
                    "monitor": "monitor" in parts[1],
                })
        return result
    except Exception:
        return []
