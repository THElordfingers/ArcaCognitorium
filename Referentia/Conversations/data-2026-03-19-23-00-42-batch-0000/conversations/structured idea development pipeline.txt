Claude:  Good question to ask before committing. Here's the honest comparison:

**Auto-inject**

The idea: scan the system map field for filenames or module names, find 
matching files in the AC repo, prepend their contents to the next API call.

The technical reality:
- The system map is freeform prose — "touches `distillation.py` and the 
Chronicle query logic". Extracting filenames from that requires either regex 
(fragile) or a Claude call to parse it (a meta-call before every message, adds 
latency and cost).
- Even if extraction works perfectly, a single Python file in AC averages 
~200-400 lines. Three files injected = potentially 1,200 lines = ~4,000 tokens 
added to every Vestibule message. At Opus rates that's material cost.
- It injects whether you need it or not. You might be asking a conceptual 
question, not a code question — and you're paying for the full file 
regardless.
- It requires `DOLIUM_REPO_PATH` to be set, and breaks silently if filenames in 
the system map don't exactly match real files.

**Slash command `/attach`**

The technical reality:
- You type `/attach distillation.py` — Dolium looks it up in the AC repo, 
reads it, prepends it to the next message only.
- Zero ambiguity about what's being attached. Zero wasted tokens on messages 
that don't need code.
- One extra env var: `DOLIUM_REPO_PATH=/home/lordfingers/ArcaCognitorium`
- If the file doesn't exist, it says so immediately. Clean failure.
- Dead simple to implement — maybe 30 lines in `conversation.py`.

**Manual paste**

Zero implementation cost. Works right now. But it's friction — you have to 
context-switch to a terminal, find the file, copy it, come back.

**The Builder's actual recommendation:**

Slash command. It's intentional — you attach what you need when you need it, 
not on every message. It's explicit — you know exactly what the entity can 
see. It's cheap — tokens only flow when you invoke it. And it's 30 lines of 
code versus a parsing system that will misfire regularly.

Auto-inject is the more elegant idea but it optimises for a problem that a 
slash command solves better with less cost and more reliability. The freeform 
system map field is not a reliable source of filenames — it was designed for 
prose, not machine parsing.
