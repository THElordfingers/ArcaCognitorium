LordFingers: debian 13 KDE pasma 6 i2c-module not loading on startup

Claude:  This is a common issue on Debian 13 (Trixie) with KDE Plasma 6 — the 
`i2c-dev` module isn't loaded automatically on boot. Here's how to fix it:

**Load it immediately (to test):**
```bash
sudo modprobe i2c-dev
```

**Make it persist on boot:**
```bash
echo "i2c-dev" | sudo tee /etc/modules-load.d/i2c.conf
```

Then verify it'll work on next boot:
```bash
cat /etc/modules-load.d/i2c.conf
# should output: i2c-dev
```

**If you also need `i2c-i801` (common for AMD/Intel SMBus):**
```bash
echo -e "i2c-dev\ni2c-i801" | sudo tee /etc/modules-load.d/i2c.conf
```

**For your Ryzen 5 7600X**, you may also want `i2c-piix4` (AMD SMBus driver):
```bash
echo -e "i2c-dev\ni2c-piix4" | sudo tee /etc/modules-load.d/i2c.conf
```

---

**Why this happens:** Debian 13 uses a minimal initramfs and doesn't auto-load 
`i2c-dev` since it's not strictly required for boot. The `/etc/modules-load.d/` 
drop-in directory is the modern systemd-native way to handle this cleanly — 
it's processed by `systemd-modules-load.service` early in boot.

After a reboot, confirm it loaded:
```bash
lsmod | grep i2c
```
