Claude:  This sounds like a KDE Plasma + display configuration corruption issue. Let's 
work through it systematically.

**The core problem** is likely that KDE's display config (`kscreen`) got 
corrupted or confused — possibly from a power event, a compositor crash, or a 
monitor going to sleep and not recovering cleanly.

**Step 1: Check what your system actually sees**

Run this and tell me the output:

```bash
xrandr --query
```

or if you're on Wayland:

```bash
kscreen-doctor --outputs
```

This will tell us if the monitors are being *detected* at all, or if it's 
purely a KDE config issue.

**Step 2: Nuke the kscreen config**

KDE stores its display layout here — stale data in this folder is the #1 
cause of monitors going dark after a crash:

```bash
rm -rf ~/.local/share/kscreen/
```

Then log out and back in (or reboot). KDE will auto-detect and reconfigure from 
scratch.

**Step 3: For the Claude app window being off-screen**

This is a classic "window remembers coordinates from a monitor that no longer 
exists" problem. Fix it with:

```bash
# Find the window ID
wmctrl -l

# Move it to visible space (replace WINDOW_ID)
wmctrl -ir WINDOW_ID -e 0,0,0,1280,800
```

Or the KDE way — click the Claude app in the taskbar to focus it, then:
- `Alt+F3` → More Actions → Move
- Then press any arrow key once to "attach" the move to your cursor
- Move it to your visible monitor and click

**My guess at what happened:** A monitor went to sleep, KDE's compositor 
stumbled trying to recover it, and wrote a broken display layout to 
`~/.local/share/kscreen/`. The `rm -rf` on that folder is almost always the fix 
for the monitor issue specifically.

What does `xrandr --query` show? Are the monitors listed as `disconnected`, or 
just `off`?
