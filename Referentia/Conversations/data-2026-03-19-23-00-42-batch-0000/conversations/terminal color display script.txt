Here's what it does and a few things worth knowing:

**Usage:**
```bash
chmod +x dircolor.sh
./dircolor.sh
```

**Flow:**
1. Prints all 256 colors in a structured grid — system colors (0–15), the 
6×36 color cube (16–231), and the grayscale ramp (232–255) — each block 
labeled with its index number
2. You enter the exact directory name (e.g. `projects`) and a color number
3. It shows a live preview of how the name will render in `ls`
4. On confirm, it writes an `LS_COLORS` entry into your `.bashrc` (or `.zshrc` 
if that's your shell)
5. Has a **show** and **remove all** mode too

**How the coloring works:**
The entry it writes looks like:
```bash
export LS_COLORS="${LS_COLORS}:*projects=38;5;214"
```
The `*dirname` glob pattern in `LS_COLORS` matches any directory with that name 
regardless of where it appears in the filesystem. It's name-based, not 
path-based — worth keeping in mind.

**One caveat:** After running, you need to `source ~/.bashrc` (or open a new 
terminal) for it to take effect. The script reminds you.

**A few things worth knowing:**

- Italic rendering depends on your terminal. Konsole supports it fully, so 
you're fine on `CastrumDigitos`.
- The `LS_COLORS` glob `*dirname` matches by name anywhere in the tree. 
Path-specific targeting isn't possible through `LS_COLORS` alone — that would 
require a different approach like a custom `ls` wrapper.
- The managed block in your `.bashrc` is self-contained between the markers. 
Running the script again to add a new entry doesn't duplicate anything — it 
reads, merges, and rewrites cleanly.
- The list view (option 3) renders each entry in its own style so you can see 
them all at a glance.
