## III. CENTRAL COLOUR AUTHORITY — VISION (unchanged from v1.0)

A central colour authority is not a palette picker. It is an instrument
of governance. Its role in the Cogniverse is to own the canonical colour
contract, generate palettes with perceptual rigour, evaluate every
meaningful token pairing across six contrast metrics, ratify palettes
with cryptographic identity, distribute the sealed palette to every
format the Cogniverse requires, and remember everything. The Chromatic
Registry is not a cache. It is an archive.

## V. MUNDANA STATE BUS DEPENDENCY & INTERIM MECHANISM

### Dependency Statement

Bureau I requires the Mundana State Bus to broadcast sealed palette
events to downstream consumers — PRAESIDIUM, GNOSIUM EXANIMA, and
any other suite application that reads `theme.json`.

The Mundana State Bus is not yet built. The broadcast channel
`mundana.resolver` is the intended publication point. Until the Bus
is live, Bureau I uses the interim mechanism described below.

### Interim Mechanism — Filesystem Watch

When a palette is sealed and `theme.json` is written, Bureau I
writes an additional signal file:

```
~/.arca/signals/theme_updated
```

This file contains the timestamp of the write and the palette
designator. It is a plain text file, overwritten on every seal.

Downstream applications that cannot yet receive Mundana events
may watch this file for modification using a polling interval
(recommended: 2000ms). On detection of a change, they reload
their QSS from `theme.json`.

This mechanism degrades gracefully: if no consumer watches the
file, nothing breaks. When Mundana is live, the filesystem watch
is retired and replaced with the bus subscription without changes
to Bureau I's seal pipeline.

The signal file path is configurable via CONFIGURATIO. Default is
`~/.arca/signals/theme_updated`.

## VI. STRUCTURED RANDOMNESS — THE JITTER FUNCTION

### The Flavour Problem

All six harmony algorithms operate in OKLAB LCH space. Without
structured randomness, the same base pair fed into the same
algorithm always produces the same derived palette. This is
determinism, not governance. The apparatus must not be a
calculator.

### The Jitter Function — `oklab_jitter()`

Each call to a harmony algorithm passes the derived LCH values
through `oklab_jitter()` before conversion to hex. The function
applies bounded random perturbation to the L, C, and H components
of each derived token independently.

```python
def oklab_jitter(
    l: float, c: float, h: float,
    l_range: float = 0.04,
    c_range: float = 0.02,
    h_range: float = 8.0,
) -> tuple[float, float, float]:
    """Apply bounded random perturbation in LCH space.

    l_range: max absolute lightness shift (±)
    c_range: max absolute chroma shift (±)
    h_range: max hue angle shift in degrees (±)

    Lead pair tokens (c_bg, c_gold) are NOT jittered.
    The base pair is the Wizard's input and is sacrosanct.
    All derived tokens receive jitter.
    """
    import random
    lj = l + random.uniform(-l_range, l_range)
    cj = max(0.0, c + random.uniform(-c_range, c_range))
    hj = (h + random.uniform(-h_range, h_range)) % 360.0
    return lj, cj, hj
```

### Jitter Ranges by Token Role

The jitter envelope is tighter for background tokens (where large
shifts would break surface hierarchy) and wider for accent tokens
(where variation is desirable).

## VII. TOKEN LOCK — HARMONIC CONSTRAINT UI

### The Constraint Problem

When one or more tokens are locked, the harmony algorithm must
work around them. In some configurations — particularly when
both an accent token and a background token are locked at hue
angles that are distant from each other and from the base pair
— the algorithm has insufficient freedom to produce a coherent
harmonic result. The palette may be technically derived but
perceptually incoherent.

The Wizard must know when this has occurred. The apparatus must
not silently produce a compromised result.

### UI Indicator Specification

When the harmony engine detects that locked tokens constrain
the derivation to the point where harmonic coherence cannot be
maintained, the following indicators activate:

**1. Palette list — per-token constraint flag**

Each locked token row in the derived palette list gains an
indicator alongside the lock icon:

```
  Sanguis   ████  #8b1a1a   Igneus Obscurus   ⊗⚑  L: 0.285
```

The `⚑` flag appears when that locked token is contributing to
a harmonic conflict. Unlocking it would resolve the conflict.

**2. Generate button — constraint warning state**

The GENERATE button gains a warning border and label when any
harmonic conflict is active:

```
┌─────────────────────────────────────────────────────┐
│  ⚑  GENERATE PALETTE  ·  Harmonic constraints active │
└─────────────────────────────────────────────────────┘
```
Border colour: Aurum Dimmus instead of Aurum.

**3. Status bar message**

```
⚑ Harmonic conflict: 2 locked tokens limit harmony algorithm.
  Unlock Sanguis or Viridis to restore coherence.
```

The warning does not block generation. The Wizard may generate
regardless. The warning informs; it does not prevent.

### Conflict Detection Logic

A harmonic conflict is declared when any locked derived token's
hue angle deviates from the harmony algorithm's expected hue
family by more than 30° in OKLAB space. The deviation threshold
is 30° because that is the boundary of the Analogous family —
the narrowest harmony model. If a locked token falls outside any
harmony family's expected range, the conflict flag activates.

## VIII. DIRTY STATE MARKER PROPOSAL

The asterisk (*) is retired per the Wizard's directive.

**Proposed replacement: the unbroken ring ◌**

The ring ◌ (U+25CC) appears in the status bar beside the stage
label whenever the working palette has unsaved changes. It is
small, legible at 10px, carries no aggressive connotation, and
reads as "open" or "incomplete" — which is exactly what an unsaved
state is. It requires no explanation.

Examples:

```
  Compositio  ◌  Unsaved         ← dirty state
  Compositio     Saved            ← clean state
  Ratificatio    Aureus Crep...   ← ratified
```

The ring disappears on save. It reappears on any change after save.
It does not pulse. It does not flash. It simply is or is not.

Submitted for Wizard ratification.

## IX. OPENING CEREMONY PROPOSAL

On first launch — and only on first launch — the apparatus
undergoes the Inductio Chromatica.

The canvas is dark. The Titulum fades in over two seconds:
title, then subtitle, then motto, each line arriving separately,
each in gold at full opacity from zero, with a 600ms gap between

Then the Feature Codex items appear one by one, top to bottom,
each lighting up in sequence over 400ms intervals from Aurum Nox
to Aurum Dimmus to Aurum — as if the five features are being
admitted to the chamber in order of standing.

from top to bottom.

No splash screen. No loading bar. No progress indicator.
The apparatus does not announce that it is loading.
It simply arrives.

Total ceremony duration: approximately eight seconds.

After the ceremony the application behaves normally forever.
A flag in the user config marks the ceremony as completed.
It never runs again unless the Wizard resets the flag manually.

## XI. PALETTE MODEL — HARMONY ENGINE WITH JITTER

The harmony engine governs all ten derived tokens. The base pair
(Fundus and Scriptura) is the Wizard's input and is never altered
by the engine. The remaining eight tokens derive from the base pair
through four sequential operations:

1. **Role derivation** — each token's L, C, and H values are computed
   from the base pair using the token's role rules (lightness ratio,
   chroma scaling, hue offset per harmony model).

2. **Harmony hue assignment** — the selected harmony model sets the
   hue family for each derived token. Complementary, Analogous,
   Monochromatic, Split-Complementary, Triadic, and Tetradic each
   produce different hue distributions across the token set.

3. **Lock pass** — any locked tokens are restored to their locked
   values, overriding harmony derivation. Conflict detection runs
   here. Flags set if needed.

4. **Jitter pass** — `oklab_jitter()` applies bounded random
   perturbation to all unlocked derived tokens. See Section VI.

The four operations run in sequence on every GENERATE press.
The result is a harmonically coherent, perceptually grounded,
genuinely varied palette.

filesystem watch. Bureau I publishes to `mundana.resolver` on
every seal. No changes to the seal pipeline are required for
this migration.
